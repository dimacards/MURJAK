# MURJAK · PHP-часть

Лёгкий бэкенд рядом со статической сборкой: управление наличием
и приём оплаты через Robokassa. Работает на бесплатном тарифе Beget
(PHP 5.6, без SSL).

## Структура

```
php/
├── api/
│   ├── stock.php          ← публичный GET, отдаёт { "1": true, ... }
│   ├── pay.php            ← редирект на оплату Robokassa
│   └── _pay-config.php    ← НАСТРОЙКИ ОПЛАТЫ (логин, пароли, режим)
├── admin/
│   ├── index.php          ← вход + управление наличием
│   ├── paytest.php        ← тестер оплаты
│   ├── diag.php           ← диагностика сервера (удалить после проверки)
│   └── _auth.php          ← сессия, CSRF, rate-limit
├── data/                  ← закрыта .htaccess от чтения снаружи
│   ├── products.json      ← каталог для PHP: id, имя, ЦЕНА, фото
│   ├── stock.json         ← наличие (пишет админка)
│   ├── invoice.txt        ← счётчик номеров заказов (создаётся сам)
│   └── orders.log         ← журнал переходов к оплате (создаётся сам)
└── .htaccess              ← DirectoryIndex + форс HTTP
```

## Куда заливать на Beget

Всё содержимое — в `public_html/`, рядом со сборкой из `out/`:

- `public_html/api/…`
- `public_html/admin/…`
- `public_html/data/…`
- `public_html/.htaccess`

Адреса:
- админка — `/admin/`
- тестер оплаты — `/admin/paytest.php`
- API наличия — `/api/stock.php`
- оплата — `/api/pay.php?items=1:1,3:2`

## Логин / пароль админки

Задано в `admin/_auth.php`:

```
ADMIN_LOGIN    = '1'
ADMIN_PASSWORD = '8'
```

Слабая защита — подбирается мгновенно. Поменять: две строки в `_auth.php`.

## Настройка оплаты

Единственный файл — `api/_pay-config.php`.

Пока стоит демо-магазин Robokassa в тестовом режиме: `RK_TEST = true`,
деньги не списываются. После регистрации своего магазина:

1. Личный кабинет Robokassa → «Технические настройки».
2. Впиши `RK_LOGIN`, `RK_PASS1`, `RK_PASS2`.
3. Поставь `RK_TEST = false`.

Там же настраиваются адреса возврата после оплаты (`RK_SUCCESS_URL`,
`RK_FAIL_URL`). Они ведут на внешние HTTPS-ресурсы (по умолчанию — Telegram),
потому что у сайта своего сертификата нет.

## Важно: цены синхронизируются автоматически

`data/products.json` (внутри `php/`) — **копия** каталога только для PHP.
Именно отсюда `pay.php` берёт цены, поэтому подменить сумму через браузер
невозможно: из URL приходят только id товаров.

Копия генерируется скриптом `scripts/sync-php-data.mjs`, который запускается
сам при `npm run build`. Руками этот файл править не нужно — правь
`data/products.json` в корне проекта.

## Защита

- Сессия в `httpOnly`-куке, CSRF-токен на кнопках.
- Rate-limit: 5 попыток входа за 15 минут с одного IP.
- Каталог `data/` закрыт `.htaccess` (никто не скачает stock.json).
- `noindex,nofollow` на страницах админки.
- Суммы платежей считаются на сервере из своего каталога.

## Права на файлы

Веб-серверу нужна запись в `data/` — там создаются `invoice.txt`,
`orders.log` и обновляется `stock.json`. Обычно достаточно 644 на файлы
и 755 на папку; если админка пишет «не удалось сохранить» — поставь 666.
