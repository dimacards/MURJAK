# Проект MURJAK: онлайн-витрина бренда одежды + Telegram-бот

## Что это
Сайт-витрина бренда одежды + Telegram-бот для управления товарами.
Покупка — через переход в Telegram продавца из карточки товара.
**Канала нет.** Категорий нет. Работник один.

## Технологии
- Next.js (App Router, TypeScript) — сайт + API + webhook бота в одном проекте
- Postgres на Supabase — база данных
- Supabase Storage — хранение фото товаров
- Prisma — ORM (через @prisma/adapter-pg, session pooler 5432)
- grammY + @grammyjs/conversations — Telegram-бот
- Vercel — хостинг

## Доменная модель

### Работник
Один человек. Его `telegram_id` хранится в `.env` как `WORKER_TELEGRAM_ID`.
Бот игнорирует все сообщения от других пользователей.
Никаких ролей и таблицы Worker.

### Товар (Product)
- **name** — название (строка, например «Cardigan Jenasis»)
- **price** — целое число рублей
- **inStock** — boolean (в наличии или нет; товар остаётся на сайте, помечается плашкой)
- **photos** — от 1 до 10 фото в Supabase Storage
- **features** — список «особенностей» товара, упорядоченный (порядок ввода). Показываются ТОЛЬКО на открытой карточке товара, не в сетке.

### Поток добавления товара
Работник пишет `/add_product` → бот ведёт по шагам:
1. фото (1–10, после каждого кнопки «ещё фото» / «готово»)
2. название (текстом)
3. цена (текстом, рубли)
4. features по одной: ввёл строку → кнопки «ещё особенность» / «готово»
5. превью + кнопки «Опубликовать» / «Отмена»

После «Опубликовать» товар сохраняется в БД, фото — в Storage. Никуда не постится.

### Поток редактирования
Работник пишет `/products` → бот показывает список → выбирает товар → меню:
- Фото (полная перезагрузка всех)
- Название
- Цена
- Features (список с ✕ у каждой + «добавить»)
- В наличии / Нет в наличии
- Удалить (с подтверждением)

### Сайт
- Главная: сетка карточек (фото + название + цена). Features в сетке НЕ показываются.
- Карточка товара: галерея фото, название, цена, **список features**, кнопка «Написать продавцу» (ссылка на `sellerUsername` из `config.json`).
- Если `inStock=false` — на карточке плашка «нет в наличии», но товар остаётся виден.
- Категорий и фильтров нет.

## Принципы работы
1. Работай этапами. Между этапами останавливайся, выводи краткий итог («сделано: X, Y, Z; проверь N»), жди от меня «продолжаем».
2. Не делай больше, чем просят в текущем этапе. Не «улучшай» соседние файлы без надобности.
3. Если для шага не хватает информации — спроси, не догадывайся.
4. После каждого этапа обновляй `README.md`: что добавилось, что проверить, какие новые команды.
5. Все секреты — в `.env`, никогда не коммить.
6. Текст в боте и на сайте — на русском.

## Структура проекта (целевая)

```
/app                  # Next.js App Router
  /api
    /bot/route.ts             # webhook Telegram
    /products/route.ts        # список товаров для сайта
    /products/[id]/route.ts   # один товар
  /products/[id]/page.tsx     # страница карточки
  /page.tsx                   # главная (сетка)
  /layout.tsx
/components
/lib
  /bot                # вся логика бота
    /index.ts         # инициализация
    /middleware.ts    # whitelist (сравнение с WORKER_TELEGRAM_ID)
    /handlers/        # обработчики команд
    /conversations/   # пошаговые потоки (add-product, edit-product)
  /db.ts              # Prisma client
  /supabase.ts        # Supabase Storage client
  /config.ts          # чтение config.json
/prisma
  /schema.prisma
config.json           # настройки магазина (storeName, sellerUsername, currency)
.env.example
.env (не коммитим)
CLAUDE.md
README.md
```
