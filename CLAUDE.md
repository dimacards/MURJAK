# Проект: онлайн-витрина магазина одежды + Telegram бот + канал

## Что это
Универсальная связка из трёх частей для магазинов одежды:
- сайт-витрина с фильтрами (только просмотр; покупка — через Telegram)
- Telegram-бот для работников магазина (загрузка/редактирование товаров)
- Telegram-канал с автопостингом товаров

Один и тот же код деплоится несколько раз — под разные магазины с разными настройками.

## Технологии
- Next.js (App Router, TypeScript) — сайт + API + webhook бота в одном проекте
- Postgres на Supabase — база данных
- Supabase Storage — хранение фото товаров
- Prisma — ORM
- grammY + @grammyjs/conversations — Telegram бот
- Vercel — хостинг

## Доменная модель

### Роли пользователей бота
- OWNER — владелец магазина (один). Может всё, включая управление работниками и категориями.
- WORKER — работник. Может добавлять и редактировать товары.
- Любой telegram_id, которого нет в таблице Worker, бот игнорирует.

### Товар (Product)
- фото: от 1 до 10 штук, хранятся в Supabase Storage
- категория (тип одежды): футболка, лонгслив и т.д. — список настраивается владельцем через бота
- размер: XS, S, M, L, XL, XXL (хардкод)
- состояние: целое число от 1 до 10
- цена: целое число рублей
- статус: ACTIVE (показывается на сайте) или SOLD (скрыт с сайта, в канале помечен ПРОДАНО)

### Поток добавления товара
Работник пишет /add_product → бот ведёт по шагам:
1. фото (от 1 до 10, после каждого кнопки «ещё фото» / «готово»)
2. категория (кнопки из списка)
3. размер (кнопки XS–XXL)
4. состояние (текстом, 1–10)
5. цена (текстом, рубли)
6. превью + кнопки «Опубликовать» / «Отмена»

После «Опубликовать»:
- товар сохраняется в БД
- публикуется альбом фото + подпись в канал, message_id альбома сохраняется
- владельцу в ЛС приходит копия с кнопками «Редактировать» и «Нет в наличии»

### Поток редактирования
Владелец жмёт «Редактировать» → бот показывает кнопки полей (фото / категория / размер / состояние / цена) + «отмена» → выбирается одно поле → запрашивается новое значение → обновляется БД + правится пост в канале.

Особый случай: если меняются фото — старый пост в канале удаляется и публикуется заново (Telegram не поддерживает удобное редактирование медиа в альбомах).

### «Нет в наличии»
Владелец жмёт кнопку → статус товара меняется на SOLD → товар скрывается с сайта → в подпись поста канала дописывается «ПРОДАНО».

## Универсализация (несколько магазинов)
Один и тот же код деплоится несколько раз. Все настройки конкретного магазина задаются через `.env` (секретные) и `config.json` в корне (несекретные). Чтобы запустить ещё один магазин — копируешь репозиторий, меняешь `.env` и `config.json`, деплоишь.

## Принципы работы
1. Работай этапами. Между этапами останавливайся, выводи краткий итог («сделано: X, Y, Z; проверь N»), жди от меня «продолжаем».
2. Не делай больше, чем просят в текущем этапе. Не «улучшай» соседние файлы без надобности.
3. Если для шага не хватает информации — спроси, не догадывайся.
4. После каждого этапа обновляй `README.md`: что добавилось, что проверить, какие новые команды.
5. Все секреты — в `.env`, никогда не коммить.
6. Текст в боте и на сайте — на русском.
